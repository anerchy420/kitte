# キッティング進捗管理

PCキッティングの進捗を、チーム全員がスマホからリアルタイムで更新・確認するためのWebアプリです。
ビルド不要の静的サイトで、データは Firebase Firestore（無料プラン）に保存します。

## できること

| 画面 | 内容 |
|---|---|
| ホーム | 本日の目標（目標＋前日繰越）、完了数、残り台数、予測（完了予定時刻、定時内か、残業見込み、延長上限でも足りない台数）、稼働メンバーの出勤と退勤、作業者別実績、全体のステータス別台数、最近の更新 |
| 一覧 | PC・YRL・伝票の検索、ステータスや作業者での絞り込み、ワンタップでステータスを進める（作業開始→梱包済み→発送済み）、まとめて変更、1台ずつの編集（形式チェックと重複警告つき） |
| 入出力 | **取り込み**：文字列の貼り付け（自動判定、括弧、区切り文字、正規表現）やExcel/CSVファイルから、列の対応を選んでプレビューしてから反映<br>**報告文**：日付を選ぶと、作業者ごと・PC番号順・梱包済み分のメール用テキストを作成（コピー、共有、.txt保存）<br>**書き出し**：Excel / CSV。未完了を含む全件から条件を絞って出力できます（下記） |
| 履歴 | 日ごとの目標、完了、達成と未達、作業者別台数、報告文の再作成、案件全体の進捗と残り日数の目安 |
| 設定 | メンバー、目標の初期値、標準作業時間、始業・定時・残業上限、休憩、PC番号の範囲、報告文の書式 |

### 計算ルール
- **完了**は「梱包済み」または「発送済み」です。梱包済みにした日が「梱包日」になり、その日の実績として数えます。
- **合計目標**は「その日の目標＋繰越」です。繰越は、前日の「合計目標 − 完了」が自動で入ります（編集できます）。
- **ペース**（1台あたり何人・分かかるか）は次のように決まります。
  - 本日の完了が規定台数（初期値3台）以上で、延べ稼働が30分以上ある場合は、実績から「延べ稼働時間 ÷ 完了台数」で計算します。
  - それ以外（朝のうちなど）は、標準作業時間（初期値50分）を使います。
- **完了予定時刻**は「残り台数 × ペース ÷ 稼働中の人数」で求め、休憩時間は飛ばして数えます。
  - 定時までに終わる場合は「定時内」、残業上限までに終わる場合は「残業見込み」、それでも終わらない場合は「繰越見込み」と表示します。
- **稼働メンバー**はホームの名前をタップして出勤と退勤を切り替えます。一日の途中で増えたり減ったりしても、そのまま反映されます。打刻を忘れたときは「時刻修正」で直せます。

### 書き出し設定（Excel / CSV）
「入出力 → 書き出し → 出力設定」で次を選べます。設定はチームで共有され、次回も残ります。

| 項目 | 選択肢 |
|---|---|
| ステータス | 未着手・作業中・梱包済み・発送済み・保留/不具合（複数選択、初期値はすべて＝未完了も含む全件） |
| 作業者 | 全員、未割当のみ、各メンバー |
| 伝票番号 | すべて、ありのみ、なしのみ |
| 梱包日の範囲 | 梱包済み・発送済みのPCだけに適用。未完了のPCはステータスの指定どおり出力 |
| 列 | PC番号、YRL番号、発送伝票番号、作業者、ステータス、梱包日、梱包日時、発送日時、更新日時、更新者、登録日時、備考 |
| 並び順 | PC番号順、作業者→PC番号、ステータス→PC番号、梱包日→PC番号 |
| Excelのシート分け | 1シート、ステータスごと、作業者ごと（＋「日別実績」シートの有無） |

ワンタップの切り替えボタンとして「全件（未完了含む）」「未完了のみ」「本日の実績」「未発送（梱包済み）」も用意しています。

### 文字列取り込みの例（自動判定）
```
【山田】
≪271≫　≪01-0973136≫　≪3912-1418-9100≫
≪272≫　≪01-0972982≫　≪3912-1418-9111≫
【佐藤】
≪310≫　≪01-0973363≫　≪3912-1418-9494≫
```
- YRL番号（`00-0000000`）、伝票番号（`0000-0000-0000`）、範囲内のPC番号を、行の並び順に関係なく見つけます。全角の数字やハイフンにも対応しています。
- メンバー名だけの行は、それ以降の行の作業者として扱います。
- 取り込むときに「すべて梱包済みにする」と梱包日を指定すれば、過去の実績もまとめて登録できます。

## 導入手順（Firebase・無料）

### 1. Firebaseプロジェクトを作る
1. https://console.firebase.google.com を開き、Googleアカウントでログインして「プロジェクトを作成」を押します。Googleアナリティクスはオフで構いません。
2. 左メニューの「構築 → Firestore Database」から「データベースを作成」を押します。
   - ロケーションは `asia-northeast1`（東京）を選びます。
   - 「本番環境モード」で開始します。
3. 「ルール」タブを開き、このリポジトリの `firestore.rules` の中身を貼り付けて「公開」を押します。
4. 歯車アイコンの「プロジェクトの設定」を開き、「マイアプリ」の `</>`（ウェブ）からアプリを登録します。Hostingのチェックは任意です。
5. 表示された `firebaseConfig` の値を `js/firebase-config.js` に貼り付けます。

### 2. 公開する（どちらか一方）

**A. Firebase Hosting（おすすめ）** ― PCで次を実行します。
```bash
npm install -g firebase-tools
firebase login
firebase use --add            # 作成したプロジェクトを選ぶ
firebase deploy               # Hosting と Firestore ルールを公開
```
`https://<プロジェクトID>.web.app` で使えるようになります。

**B. GitHub Pages** ― リポジトリの Settings → Pages で、このブランチの `/`（root）を公開します。無料プランの場合、Pagesを使うにはリポジトリを公開（public）にする必要があります。

### 3. 使い始める
1. URLをスマホで開きます。「ホーム画面に追加」をしておくとアプリのように使えます。
2. チーム共通の**パスコード**を入力します（推測されにくい8文字以上を推奨）。全員が同じパスコードを使います。
3. 自分の名前を選ぶか、追加します。
4. 「入出力」タブから、PC番号とYRL番号の一覧（Excelなど）を取り込みます。
5. 「設定」で目標台数、標準作業時間、休憩時間などを確認します。

### セキュリティについて
- パスコードはSHA-256でハッシュ化され、データの保存場所のID（64桁）になります。パスコードそのものはどこにも保存されません。
- Firestoreのルールでは保存場所の一覧取得を禁止しているため、パスコードを知らない人はデータにたどり着けません。
- パスコードを変えると、別の空のデータ置き場になります。変えたいときは、Excelで書き出してから新しいパスコードで取り込み直してください。

### 無料枠の目安
- PCは100台ずつ1つのドキュメントにまとめて保存しています。500台でも読み込みは数回で済み、Sparkプラン（無料）の上限（1日あたり読み取り5万回、書き込み2万回）に対して十分に余裕があります。

### 電波が不安定なとき
- 画面上部の表示が「送信中」や「オフライン」でも操作を続けられます。操作は端末に保存され、電波が戻ると自動で送信されます。

## 開発
```bash
npm test     # 計算・取り込みロジックのテスト（Node 18以上）
npm start    # http://localhost:8080 で起動
```
`js/firebase-config.js` の `apiKey` が空のままだと**デモモード**で起動し、データはそのブラウザ内だけに保存されます。動作の確認に使えます。

| ファイル | 役割 |
|---|---|
| `index.html`, `css/style.css` | 画面 |
| `js/app.js` | 画面の動作 |
| `js/logic.js` | 予測計算、取り込み解析、報告文の作成（Firebaseに依存しない処理） |
| `js/store.js` | Firestoreとデモ用の保存処理 |
| `firestore.rules` | Firestoreのセキュリティルール |
